# S17 Sprint Report - Reputation, Reviews, Favorites, Relationships, and Book Again

- Sprint: S17
- Completed tasks: NS-170 reputation engine, NS-171 settled-booking reviews, NS-172 persistent favorites, NS-173 relationship history, and NS-174 Book Again.
- New files: config/reputation.lua, sql/015_reputation.sql, server/domain/relationship.lua, the review/favorite/relationship repositories, the reputation/review/favorite/relationship/Book Again services, server/dev/s17_smoke.lua, and tests/s17_reputation_review_contracts.lua.
- Persistence: Migration 015 adds bounded client reliability, NPC review aggregates, and relationship trust fields. Migration 016 widens last_booking_id for token-shaped booking IDs without changing the checksum of the original S17 migration. Repository writes use allowlisted columns and optimistic versions; duplicate review/favorite/relationship operations are replay-safe.
- Reputation contract: Settled booking events update worker professionalism/discretion/reliability and client reliability with bounded, configurable deltas. Cancellation and no-show penalties are distinct. Intermediate COMPLETED events do not score before SETTLED, and client ratings are never written directly by the client.
- Review contract: Reviews require a settled booking, actor ownership, a bounded rating, and a valid worker. One review is accepted per booking; aggregate rating and count updates are versioned and exposed through privacy-safe DTOs.
- Favorite contract: Clients can add, list, and remove persistent NPC workers. Pair uniqueness is enforced by the repository and workers are returned through safe DTOs.
- Relationship contract: Actual settled booking history increments interactions and trust, derives the REGULAR state at the configured threshold, and leaves cancelled/interrupted bookings out of the interaction count. Event-bus projection and the booking-event ledger prevent double counting after replay or restart.
- Book Again contract: The worker is rechecked for availability, an optional previous booking is server-verified for worker consistency, a fresh quote is requested through the normal booking pipeline, previous prices are ignored, and confirmation accepts only the new quote ID.
- Public API changes: Added NUI routes for reviews, favorites, relationships, and Book Again. Added development-only S17 smoke commands; no server.cfg edits are required.
- Automated checks: lua tests/run.lua, luac -p over all Lua files, npm --prefix web run build, and git diff --check pass. The S17 suite covers bounded/versioned reputation, settled-only review and aggregate behavior, duplicate protection, favorite persistence, relationship threshold/cancellation/replay behavior, and fresh Book Again quotes.
- Security and recovery: Inputs are allowlisted and validated at service boundaries; actor ownership and worker availability are server-side checks; SQL fields are repository-controlled; review responses never include the raw booking record; projection failures are isolated after booking commit, retained in the EventBus bounded retry queue, and can be rebuilt from the booking-event stream.
- Live verification: FXServer smoke remains deployment-specific. Use the emitted S17 command help/results after restarting the resource; no manual configuration injection is part of the implementation.
- Exit Gate result: PASS for S17 contracts and integration wiring. The implementation plan has no remaining S17 coding item.
